# AI Chinese 7.0 · 横屏版

7.0 黑板课堂的横屏版：手机横过来拿着上课。原有教学内容、两个主题和三套配色保持不变；
除了把各屏重排到横屏，结课后还多了一段「阿岚早餐铺」三人情景对话，再进入原来的生活剧场。

直接打开 `index.html` 即可（`file://` 就行）。或者在上一级目录起服务：
`python3 -m http.server 8931`，然后访问 `/ai-chinese-7-landscape/index.html`。
桌面上默认是一台横放的手机框（900×420，屏幕 884×404，灵动岛画在左边）；
在真手机上打开会自动铺满，竖着拿会请你先转过来。`?frame=0` / `?frame=1` 可以强制切换，
`?theme=pop&pal=matcha` 这类参数和 7.0 一样能用。顶栏多了一个「竖版 7.0 ↗」，方便来回对照。

## 为什么不是「转过来就行」

`screenshots/为什么要重排-7.0直接横过来.jpg` 是 7.0 原样在 844×390 下的样子：黑板被压成一条缝，
老师被裁掉半边，铺满屏宽的「上课」和讲解时那排四个钮把一半高度吃掉了。
原因是 7.0 的板下沿是按竖屏像素写死的（讲解屏 `--board-bottom:288px`），竖屏有 884px 高、横屏只有 404px，
这个数一减就没了。横屏最缺的是高度，宽度反而富余——所以这一版不是缩放，是重排。

## 这间教室横过来以后

横过来以后黑板终于有了黑板该有的比例：一块宽板几乎铺满画面，老师站在板的右端，
要教的东西写在她左边那三分之二；板下面一条窄窄的地面，左边是字幕（她说的话），右边是你要按的按钮。
这是这一版唯一的「大动作」，其余都尽量安静。

实现上，每一块教室屏（讲解、面谈、练习、今天、老师）都是同一张 CSS 网格：两列「写字区 | 她」，
四行「顶排胶囊 | 进度条 | 主体 | 地面」。黑板（`.dh::before`）、粉笔槽（`.dh::after`）和她（`.dh-art`）
仍然是绝对定位，但都写了 `grid-row / grid-column`——绝对定位元素的包含块会变成那块网格区域，
于是板的下沿自动停在「地面」那一行上面：字幕多一行，板就跟着矮一截。竖版要给每块屏手算 `--board-bottom`，
横版不用算了，这也是它在三种手机尺寸上都不变形的原因。

她那一列宽 `clamp(196px, 33%, 300px)`，但写成 `minmax(--herw, max-content)`：
右下角的按钮簇更宽的时候（小屏、英文界面里「Log it and go practise」这种），这一列跟着变宽、写字区让出来，
而不是按钮簇往左压到字幕上。亮主题下她整个人仍然站在板沿以内，这条 7.0 的规矩没变。

**她的脸永远不被挡**，这是排选项时最硬的一条约束。面谈的选项默认只往她身前伸 60px——
她的脸从站位框左起约三分之一处才开始，60px 只压到她肩膀的虚化边；只有第 1 问的六个选项需要更宽，
它的题目两行高、选项落在她下巴以下，可以伸到胸口。判定屏那张理由纸同理：结论照竖版那样三行写在板上，
纸从她下巴以下才开始。中途我试过把结论压成一行省高度，结果纸上移到她脸的高度，在 932×430 上把脸盖住了 41%——
所以退了回来，宁可那张纸要滚两行。这些数都是下面那个布局检测器按立绘真实渲染位置量出来的，不是估的。
（上面说的是半身照站位框的老师；杨老师和林老师这两位去背全身像见下一节。）

## 杨老师与林老师：整个人站在板前（从 7.1 搬来）

7.1 有两位站在板前的老师：林老师的透明底真人全身像，以及她的 3D 卡通版杨老师。两人都直接放在黑板和玻璃控件之间，不裁、不羽化、不压暗调，
板上有一层往右下落的影子，脚下一团落影，整双鞋踩在地上（做法和出图过程见 `../ai-chinese-7.1/README.md`）。
横屏版把两位原样接了进来：`lesson-core.js` 和 7.1 相同（杨老师排第一、是默认老师；林老师排第二），
`dhArt()` 有去背图就吐 `.dh-cut`，加载失败自动退回站位框，四张图都拷进了 `assets/`。
其余九位老师没有去背图，照旧走半身照站位框。

7.1 的站位是按竖屏定的（头顶 100px、身高 0.86 屏高、粉笔尖对到 56% 那条线），横屏要重新算，写在
`landscape.css` 最后「去背全身像」那一段：

- **全身，0.9 倍屏高。** 横屏只有 404px 高，要让整个人连鞋站在屏里，她就只有约 364px——
  比竖屏小一半。杨老师头大，脸仍然认得清；林老师的脸约 37px 宽。这是「完整的人」在横屏上的代价，见文末「没做的」。
- **贴着屏的右下角站，不进网格。** 右边让出安全区再空 16px，鞋底离屏底 8px。这样换屏的时候她纹丝不动
  （7.1 的「全站一条站位线，换屏时变的是板」），变的是写字区的宽度。
- **她那一列收窄。** 半身照那一列要 300px 宽；两位去背立绘只有约 104–106px 宽，所以那一列改成当前立绘宽 + 34px。
  写字区因此变宽了，今天页那行课时目标现在一行写得下。按钮簇更宽的屏（讲解的四颗方键）那一列照旧跟着变宽。
- **比例按老师取。** 林老师立绘 617×2168，杨老师 633×2172；`cutGeo.ar` 会写成 `--cut-ar` / `--cut-ar-w`，
  `aspect-ratio`、她那一列和所有让位都按实际宽度算，不会把杨老师横向拉宽。
- **选项、理由纸停在她左边。** 面谈的选项卡和判定屏的白纸一律停在她捏粉笔的那只手左边 12px，不压她；
  判定屏的纸因此比方老师那版窄一点，要多滚一截。
- **「正在讲话」挪到她头的左边。** 原来在右上角，正好是她头顶的位置。
- **腿伸出板下沿，落在墙前；右下角的按钮簇压在她小腿前面**——7.1 的说法是「像站在讲台后面」。
  老师 tab 没有按钮簇，那一屏她连鞋都露着。

对照图在 `screenshots/对照-方老师vs林老师-*.jpg`（左边半身照站位框，右边林老师），
林老师单屏在 `screenshots/林老师-*`；杨老师的关键屏在 `screenshots/杨老师-*`。
之前选过别的老师的话（`cc.teacher` 和 7.0 / 7.1 共用），到「老师」tab 点「换一位老师」，
或者顶栏「重新评估」，就能回到默认的杨老师。

## 按钮：收进右下角拇指区

这是动手前和你确认过的方向。竖版里铺满屏宽的长按钮（上课 / 下一题 / 继续 / 开始…）缩成一颗短键帽，
次要的（上一题、听一遍、先回首页、目标定低一点）变成小胶囊，一起收在右下角、老师脚下。
DOM 里的先后各屏不一，统一用 `order` 排：次要的在左，主按钮永远在最右——横握时右手拇指正好落在那儿，
而且每一屏都在同一个位置。讲解时那排四个控制钮（暂停 / 重说这句 / 说慢点 / 没听懂）缩成四颗方键挤在她脚下；
讲完以后「暂停」「说慢点」已经没意义，收掉，剩下两颗排在「继续」左边。

练习段原本的问题是：流程按钮写在内容里，跟着内容一起滚，横过来只有 400px 高，内容一长按钮就掉到折线以下。
所以加了一个 `toThumb()`：渲染完把 `.lbody` 里那几颗流程按钮拎出来，放进右下角固定的 `.thumb`。
只挪 DOM 节点，id 不变，事件绑定都在挪完之后才做，逻辑一行没动。跟读和自由表达的「按住说话」也挪了过去——
按住说话这件事，就该在右手拇指底下。今天页往上滑出来的那些卡片里，按钮也不再铺满，缩成右对齐的短键帽。
横版里没有一颗整行宽的按钮。

## 导航：左侧竖条

今天 / 课程 / 老师三个 tab 从底部那颗横胶囊竖过来，贴在左边（灵动岛旁边），当前项从圆钮展开成「图标 + 字」。
横屏宽度富余、高度紧，导航放侧边不占高度。有导航条的屏，黑板整体往右让开它。
铺满视图下那几颗原型开关（主题 / 配色 / 手机框）只在这三个 tab 页出现，竖着收进导航条上方那块空墙——
放在顶上居中会压住课堂顶排的胶囊，第一版就是这么压的。

## 课后情景对话

结课页的主按钮现在先进入 `海棠街 · 阿岚早餐铺`，而不是直接进剧场。你、林浩、阿岚三个人用本课的
「点 / 分 / 几 / 现在 / 今天 / 明天 / 星期 / 号」完成九句对话：先问现在几点，再问今天几号，
最后约好明天下午三点十分。中间有三道三选一，答错会解释是钟点、日期还是星期不对，可以立即重答；
最后跟读「明天下午三点十分见」。完成页给出三组带走表达，然后才进入原有六幕生活剧场。

- 交互状态存 `cc.scenarioDone / cc.scenarioStarted / cc.scenarioBeat`；中途退出会从当前句续上。
- 林浩和阿岚复用 `scene-moving.jpg`、`scene-alan.jpg` 头像；只新增一张早餐铺背景 `scenario-breakfast.jpg`（1536×1024）。
- 中、英、印尼三种界面共用同一套对话数据；不自动播放音频，每句可点读或慢速重听。
- 跟读复用按住说话的手势，但原型不录音评分，只提示学习者自己对照示范。

## 铺满视图、小手机与竖着拿

缺省时按「像不像一台手机」判断视图：触屏、且短边 ≤ 540px 就铺满，否则看手机框。
7.0 那条「宽度 ≤ 900 就铺满」在这里不成立——横屏手机的宽度能到 932px。
视图偏好存在 `cc.viewL`，和 7.0 的 `cc.view` 分开：同一个源下两版共用 localStorage，
在竖版里点过「铺满」不该把横版也带着铺满。其余 `cc.*`（老师、进度、主题、配色）两版仍然共用，这是故意的。

安全区在手机框里是写死的（左边让出灵动岛），铺满时取 `env(safe-area-inset-*)`，最少留 14px。
铺满且竖着拿的时候，盖一层「把手机横过来」，给两条退路：看竖版 7.0，或者就在这台设备上看手机框。

矮屏（高 ≤ 390px，比如 iPhone SE 横过来的 667×375，或者 Safari 带着地址栏）字号和间距收一档，
面谈题目下面那行「选最主要的一个」这类提示藏掉，第 1 问的选项描述收成一行（超出用省略号）——
提示行一藏选项就上移到她脸的高度，所以矮屏上第 1 问也改回只伸 60px 的窄版；
窄屏（宽 ≤ 720px）讲解的四颗方键再小一号。手机框是固定的 884×404，不会进这两段。

## 顺手修掉的几处 7.0 原有问题

这几处是把检测清单补全以后才量出来的，7.0 里同样存在。**只在横版文件夹里修了，7.0 原样没动**；
需要的话我可以把同样的改动搬回 7.0。

多巴胺主题里，面谈选项按位置轮色的规则（`.opt:nth-child(...)`）写在选中态 `.opt.sel` 后面、特异度相同，
于是选中项的主色底被浅色底盖掉，只剩白字——第 6 问默认选中的「25 分钟」几乎看不见。横版把选中态提了一级。

跟读和自由表达里有几处 5.0 留下的行内颜色：拼音用 `--violet`，英文和「老师问你：」用 `--muted`。
它们压在板上，亮主题下是棕字配绿底，冷调下是紫字配深底。横版不动 JS，用属性选择器把它们换回粉笔色。
同一屏的「听老师读」原来是绿玻璃配橙字，亮主题下改成白键帽。

段末一问答完以后，没选的那项整块压成半透明，编号「3」只剩 0.23 的亮度差（阈值 0.25），改成不透明、用浅字。

今天页的英文界面里，老师那句话会显示两遍（大字一遍、小字一遍）——英文模式下两处取的是同一句。
横版只在两句不同时才出小字。另外课程表的单元行在按钮里默认居中，改成了左对齐；弹层里的按钮（剧场求助、街区经历）也从整行宽收成了右对齐的短键帽。

## 改了 `index.html` 的哪几处

`skin.css` 和 7.0 逐字节相同；`lesson-core.js` 和 7.1 逐字节相同（7.0 + 杨老师、林老师）；`assets/` 是 7.0 的十九个素材加两位老师共四张图。`index.html` 动了这几处，其余原样：

1. 头部脚本 —— 「像不像手机」的视图判断，偏好改存 `cc.viewL`；加载 `landscape.css`
2. 外壳 —— 品牌字改成「横屏原型」，顶栏加「竖版 7.0 ↗」，加「把手机横过来」那一层
3. `syncChrome()` —— 上面几处的三语文字
4. `viewPref()` / `syncView()` / `fitFrame()` / `setView()` —— 新的判断规则；横放的机身比竖放宽一倍多，窄面板里缩放下限从 0.5 放到 0.3
5. `renderLesson()` —— 外层加 `data-seg`（让每种练习段能各自排版）和一个空的 `.thumb`，渲染完调 `toThumb()`
6. `renderTalk()` —— 同上，加 `.thumb`、调 `toThumb()`
7. `toThumb()` —— 新增的那一个函数，见上面「按钮」一节
8. `renderToday()` —— 英文界面不再重复显示老师那句话
9. `runSmoke()` —— 加了两条断言：每个练习段的流程按钮必须已经进了拇指区，段末一问的「继续」也是；
   另把 7.1 那条「有去背图的老师必须真的站到板前、没有的走站位框」搬了过来，并核对当前立绘的宽高比
10. `dhArt()` / `cutVars()` —— 有去背图就吐 `.dh-cut`，加载失败自动退回站位框；按 `cutGeo` 写入宽高比，横屏的所有让位都从实际立绘宽度算

`landscape.css` 叠在 `skin.css` 后面，只管布局、基本不碰颜色。为了压过 `skin.css` 里多巴胺主题那些
`[data-theme="pop"] .xxx` 规则，凡是可能打架的选择器都写成 `[data-theme] .xxx`——特异度相同、出场更晚，所以赢，
冷调也一样命中。以后 7.0 的皮再改，把新的 `skin.css` 拷过来，这一层基本不用动。

## 自检

四道，改完都要跑。前两道是 7.0 就有的，第三道是这一版新写的，第四道是 7.1 写的（去背全身像进来以后才需要）：

```bash
cd "AI Chinese 5.0" && python3 -m http.server 8931 &
cd ai-chinese-7-landscape && npm i playwright && npx playwright install chromium
# 1. 冒烟：浏览器打开 index.html?smoke=1
node check-contrast.js cool pop/citrus pop/berry pop/matcha                 # 2. 低对比文字
node check-layout.js cool pop/citrus pop/berry pop/matcha                   # 3. 横屏布局（手机框）
NOFRAME=1 SIZES=667x375,844x390,932x430 node check-layout.js pop/citrus      #    再加三种真机横屏
LANG_UI=en node check-layout.js pop/citrus                                  #    英文 / 印尼语（id）界面
node check-occlusion.js cool pop/citrus                                     # 4. 字有没有被杨老师挡住
```

几个检测器默认用杨老师；`TEACHER=lin` 查林老师，`TEACHER=fang` 换回半身照站位框的老师。

**冒烟测试**现在是 50 项全过。它真的点一次「上课」，把 17 段逐段走完、11 组讲解逐句放完并答一次段末问、
十一位老师各渲染一遍，两位去背立绘还会核对是不是自己的宽高比；再走完情景介绍、九句对话、三道选择、跟读和完成页，
最后把剧场演到谢幕。横版另外断言流程按钮都进了拇指区。

**低对比检测**从 7.0 拷来，改了地址、视图键和元素尺寸上限（横屏里字幕能有 500px 宽），
并补了七个 7.0 清单没覆盖、而这次真出过问题的状态（第 6 问默认选中、第 3 问答完、段末一问答完、讲解讲完、
自由表达、听力答错、老师聊天中），再加上情景介绍、选择、答错、跟读和完成页五屏。冷调、柑橘各 32 屏，现在 0 处。

**布局检测**（`check-layout.js`）是横屏最需要的那一道。截图评审看不出来、但横屏最容易出的事有四类，它每屏都量：
可点的东西有没有落到安全区外（灵动岛那一侧、屏幕边缘）；在它中心点 `elementFromPoint` 拿到的是不是它自己
（没被别的玻璃条压住）；主操作是不是不用滚就完整可见；她的脸有没有被卡片、按钮盖住超过 15%
（脸的位置按立绘实际渲染算：`object-fit:cover` + `object-position` 换算出图片在框里的位置，再取脸在原图里的大致范围）。
被滚动容器裁掉的元素不算（那是滚动），绝对定位元素只看它包含块链上的滚动祖先——第一版没区分这一点，
把相对整屏定位的「开始」误报成了被介绍栏裁掉。

它一路翻出来并已修掉的真问题有：剧场选择题那一拍「再听一遍问题」被挤到面板折线下；讲完时「没听懂」被「继续」盖住；
铺满视图下课时顶排被 7.0 的 `html.bleed .lh{top:38px}`（给竖版状态栏让位的）往下推了 38px、和选项叠在一起；
印尼语里六个入口折成两行，聊天记录往上长时盖住了第二排；以及上面说的那几处挡脸。
本轮冷调、柑橘各 51 屏的手机框全量回归为 0 处；另在四套配色、三种真机横屏和中英印界面下单独检查情景页，也均为 0 处。

它还会列出「写字区要滚动」的屏，作为提示、不算失败。现在剩下的都是本来就该能滚的阅读区：
判定屏的理由纸（手机框里要滚两行，竖版里这张纸也要滚）、字形卡、声调实验室、剧场选择题的面板；
英文界面第 1 问差 14px，印尼语差 31px。主按钮在这些屏上都一直在拇指区，不受滚动影响。

**遮挡检测**（`check-occlusion.js`）从 7.1 拷来，改了地址和视图键，脸框按当前老师的 `cutGeo.face` 取：把她的透明通道画进 canvas 算出真实轮廓，
逐字采点，看有没有字被她挡住、有没有字没垫任何底就直接压在她身上、她的脸有没有被卡片盖住。
杨老师在四个组合 × 26 屏（含十一组讲解板书）三项都是 0；压在她身上但隔着按钮或字幕底的有 128 处，就是那几颗压在她小腿前的按钮，不算。
林老师在冷调里单独回归 26 屏也是 0；布局检测和低对比检测在冷调、柑橘下也各跑了一轮，都是 0。

`file://` 直接打开也验过：真点一遍选老师 → 面谈六问 → 判定 → 上课，零请求失败、无脚本错误、三颗配色点正常。

## 没做的

- **没上真机。** 所有尺寸都是在 Chromium 里模拟的触屏视口，没在 iPhone 的 Safari 上实测。
  有两件事模拟不出来：一是 `env(safe-area-inset-*)` 在模拟里是 0，所以截图里左右只留了 14px，
  真机横屏两边各有 47–59px，写字区会再窄一截（布局会自己让，但没量过）；二是 Safari 横屏时地址栏的收放。
- **没有锁定横屏。** `screen.orientation.lock()` 要先进全屏，iOS Safari 也不支持，所以竖着拿时是请人转过来，而不是强制转。
- **竖版和横版是两个文件夹，不是一个转了屏就自己切换的 App。** 如果正式版要「一个 App、转屏自适应」，
  可以把 `landscape.css` 整体包进 `@media (orientation: landscape)` 合进 7.0，再把 `toThumb()` 改成只在横屏时挪——这一轮没做。
- **小屏上有几块要滚。** 667×375 下判定屏的理由纸要滚 95px 上下，第 1 问的选项描述被收成一行；
  再矮的屏（Safari 带地址栏、330px 上下）没专门调过。
- **课后剧场仍没有重新套壳**，和 7.0 一样只换了设计令牌；这一轮只把它排成了横屏的左右两栏。
- **情景对话是固定脚本**，不做自由 AI 对话、语义识别或自动发音评分；只验证听辨、选句和开口跟读这一层。
- **两位去背老师在横屏上偏小。** 要整个人连鞋站在 404px 高的屏里，她们只有竖屏的一半大；林老师的脸约 37px 宽，表情看不太清。
  如果更在意老师的存在感，可以改成「膝盖以上」的取景（她放大一倍多、小腿出屏），代价是不再是 7.1 定的「整个人、不裁」——这一轮没这么做。
- **右下角的按钮簇压在去背老师的小腿和鞋前面。** 按钮簇和她都在右下角；只有老师 tab 那一屏她连鞋都露着。
- **其余九位老师没有去背图**，仍走站位框；管线见 `../ai-chinese-7.1/gen/prompts.md`。
- **半身照的「脸在哪儿」还是写死的平均比例**（横向 35%–64%、纵向 11%–31%）；去背图已经按每人的 `cutGeo.face` 取。换新的半身照仍要跟着改。
- 其余九位老师仍不是去背图，另外十一个单元的课时内容也仍然没有，和 7.0 一样。
